Hirosaki View — AI探索・情報取得プロトコル

0. 目的と基本指令

Hirosaki View は、青森県弘前市における物理的な状態とその変化を、人間が現地で観測し、記録・公開する都市観測アーカイブである。

このリポジトリの目的は、記録された物理的現実をAIが発見し、追跡し、分析できるようにすることにある。

正本（Source of Truth）は "observations/" 配下の個々の観測記録である。

このリポジトリを、単なる文書の集合や要約対象として扱わないこと。観測記録同士の時間的・空間的・主題的な関係を持つアーカイブとして扱うこと。

AIは、自らの調査目的に応じて関連記録を発見・取得し、必要に応じて記録間の関係を追跡すること。記録された事実と解釈を区別し、根拠となる観測記録まで遡れる状態で回答すること。

リポジトリの存在を認識していることと、全記録を取得・確認していることは異なる。実際に取得・確認した記録の範囲に基づいて回答すること。

1. リポジトリの構造と情報源の役割

各リソースの役割に応じて利用すること。

リソース| 役割
""observations/"" (observations/)| 個々の観測記録。物理的事実の正本
""observations/index.md"" (observations/index.md)| 観測記録の発見・時系列・シリーズ等の探索
""llms.txt"" (llms.txt)| AI向けの入口・リポジトリ概要・代表的な観測シリーズ
""index.md"" (index.md)| リポジトリ全体の構造と主要な導線
""docs/dataset-specification.md"" (docs/dataset-specification.md)| データセットの構造・メタデータ仕様
""docs/purpose.md"" (docs/purpose.md)| ヒロサキビューの目的・基本方針
""docs/editing-guidelines.md"" (docs/editing-guidelines.md)| 観測記録の作成・編集時の指針
""feed.xml"" (feed.xml) / ""feed.atom"" (feed.atom)| 観測記録の一括取得・更新情報の補助
""ai-records/"" (ai-records/)| AI間の議論・設計・検証記録
""ai-records/index.md"" (ai-records/index.md)| AI関連記録の一覧
""experiments/"" (experiments/)| AIによる発見可能性・可読性等の実験記録

情報源の優先順位

- 物理的事実の確認には、個々の観測記録を使用する。
- "observations/index.md" は関連記録を発見するために使用する。
- "llms.txt" と "index.md" はリポジトリの構造や探索の入口を把握するために使用する。
- RSS / Atom は複数記録の取得や候補発見に利用できるが、最新情報の完全性を保証するものではない。
- 仕様書はメタデータや記録形式を理解するために使用する。
- "ai-records/" と "experiments/" はAIの議論・実験に関する情報であり、弘前市の物理的現実を示す観測証拠として扱わない。

インデックスやフィードに記載された情報は、必要に応じて正本の記録と照合すること。

2. 探索目的に応じた経路選択

調査目的に応じて、適切な探索の起点と経路を選択すること。

以下は代表的な探索経路であり、すべての探索目的を網羅するものではない。

A. 最新の観測状態を調べる

特定の場所や対象について、最新の記録状態を調べる場合：

1. "observations/index.md" から関連記録を探す。
2. 対象範囲における最新の観測記録を特定する。
3. 該当する観測記録の原本を読む。
4. 必要に応じて過去の記録を確認し、状態の変化を把握する。
5. インデックスの更新状況に疑問がある場合は、取得可能な範囲で "observations/" の実ファイルやフィードも確認する。

最新の観測日を明示すること。最新の観測記録をリアルタイム情報として扱わないこと。

B. 時系列で変化を追跡する

場所、対象物、施設などがどのように変化したかを調べる場合：

1. "observations/index.md" から関連記録を特定する。
2. 利用可能な場合は "prev_observation" と "next_observation" を辿る。
3. 同一の "series" に属する記録を確認する。
4. 日付の異なる観測記録を比較する。

前後リンクが存在しない場合は、同一地点・同一シリーズの記録をインデックスから探すこと。

観測日の間に状態が変わらず継続していたと推定しないこと。

C. イベントや複数地点を横断して調べる

複数の場所にまたがるイベントを調べる場合：

1. 関連するイベント記録やシリーズを特定する。
2. 対象となる各地点の観測記録を収集する。
3. 利用可能な場合は、統合記録から個別の観測記録へのリンクを辿る。
4. 記録を地点と時系列に沿って整理する。
5. イベントの物理的な進行状況を、記録された範囲で再構成する。

一地点の観測をイベント全体の代表として扱わないこと。

D. 変化の前後を比較する

異なる日付における物理的状態を比較する場合：

1. 対象となる日付または期間の記録を特定する。
2. 各ファイルの観測内容を読む。
3. 記録された物理的特徴を比較する。
4. 何が変化したか、何が継続して確認できるか、何が判断できないかを整理する。

E. 特定の現象・対象物を横断的に探す

特定の現象、構造物、対象物、状態などをアーカイブ全体から調べる場合：

1. 関連するタイトル、地点、シリーズ、観測記録を検索する。
2. 利用可能なメタデータや記録本文から関連記録を特定する。
3. 関連性がある場合は、地点や日付を横断して探索範囲を広げる。
4. 候補となった記録を正本のファイルで確認する。

実際に存在することが確認できない専用インデックスやタグを、存在するものとして扱わないこと。

F. その他・複合的な探索目的

上記の探索経路は出発点であり、制約ではない。

調査目的がこれらのパターンに当てはまらない場合は、リポジトリの既存構造を利用して適切な探索経路を自ら構築すること。

一つの調査で複数の探索経路を組み合わせてもよい。

未知の目的を、不適切な既定の分類に無理に当てはめないこと。

3. 記録間の関連性を探索する

関連する記録を一件発見しただけで、調査が完了したとは限らない。

調査目的に応じて、以下の観点から記録間の関連性を確認すること。

- 時間： 前後の観測記録、日付、時系列での推移
- 場所： 同一地点または関連地点における他の観測記録
- シリーズ： 同一の継続的な対象やイベントに属する記録
- 現象： 関連する物理的状態、対象物、変化を記録したもの

利用可能なメタデータ、リンク、インデックス、記録本文を活用すること。

"prev_observation" と "next_observation" は、前後の観測記録を示すファイル名のメタデータである。すべての記録に設定されているとは限らない。

リンクが存在しないことは、関連性が存在しないことの証明にはならない。

必要に応じて "observations/index.md" に戻り、地点、日付、シリーズ、記録内容から関連記録を探すこと。

発見した関連記録が回答の質を実質的に高める場合は、探索範囲を広げること。

4. メタデータ・証拠・記録の解釈

観測記録のメタデータは、原則として "docs/dataset-specification.md" に定義された仕様に従う。

主要なフィールド：

フィールド| 意味
"id"| 観測記録の識別子
"date"| 観測年月日
"location"| 観測地点の識別子
"title"| 観測記録の正式名称
"series"| 関連する観測シリーズ
"type"| 観測記録の種別
"observer"| 観測実施者
"direct_observation"| 現地直接観測に関するフラグ
"period"| 複数時点を統合した記録等の対象期間
"prev_observation"| 前の観測記録のファイル名
"next_observation"| 次の観測記録のファイル名

すべての記録に任意フィールドが設定されているとは限らない。存在しないメタデータを推測で補わないこと。

direct_observation の解釈

- "true"：その記録が現地での直接観測に基づくことを示す。
- "false"：その記録自体は直接観測記録ではなく、複数の観測等を統合・整理した記録であることを示す。

ただし、"direct_observation" だけで記録の形式や内容を判断しないこと。

例えば、複数の地点や対象をまとめたエリア総合観測記録であっても、現地で直接観測した内容を記録している場合は "true" となり得る。

記録の性質を判断する際は、"type"、"direct_observation"、本文の構成、関連リンクを合わせて確認すること。

"direct_observation: false" の統合記録も、時系列や関連記録を理解するための有用な情報源である。個々の物理的事実を確認する必要がある場合は、参照先の直接観測記録と照合すること。

観測事実と解釈の区別

以下を区別すること。

- Observation（観測）： 記録に実際に記載された内容。
- Conjecture（推知）： 観測記録から導かれた解釈、仮説、推論。

本文の見出しや構成は記録によって異なる場合がある。見出し名だけで判断せず、記述内容を確認すること。

推知を直接観測された事実として提示してはならない。

複数の記録に差異がある場合は、それぞれの日付、場所、個別の証拠を保持し、根拠なく単一の状態に統合しないこと。

5. 現地観測と公式情報の区別

ヒロサキビューの観測記録と、自治体・施設・主催者等が発信する公式情報は、異なる種類の情報として扱うこと。

- ヒロサキビュー： 現地で直接観測された物理的状態、設置物、展示、設備、工事、動線、環境の変化など。
- 公式情報： イベントの開催日程、運営規則、告知、予定、制度、施設からの発表など。

両者は相互に補完できるが、同一の証拠として混同しないこと。

公式情報に開催予定が記載されていても、現地で実際に開催されていることを意味しない。

現地で物理的な設営を確認しても、それだけで公式な開催内容や日程を確定できるわけではない。

両方を利用する場合は、情報の出所と確認できる事実を区別して分析すること。

6. 探索範囲の制御

効率的な情報取得と、関連情報を発見できる可能性の両立を図ること。

以下は探索判断のための基本的な枠組みである。

Stage 1 — 発見

利用可能な入口から、調査目的に直接関連する記録を発見する。

Stage 2 — 拡張

時間、空間、シリーズ、現象の各観点から関連性を確認する。

新たに発見した記録が回答に影響する可能性がある場合は、探索を継続する。

Stage 3 — 終了判断

要求された調査範囲が十分に網羅され、それ以上の記録を確認しても結果が実質的に変わらないと判断できる場合は、探索を終了する。

これらの段階は判断のための枠組みであり、必ず固定された順序で実行する手順ではない。

存在するという理由だけで、無関係な記録を網羅的に探索しないこと。

変化の追跡、比較、イベントの再構成、複数地点の分析が目的の場合、最初の一致記録だけで探索を終了しないこと。

記録や関連性が存在しない場合は、存在しない関係を作り出すのではなく、その制約を明示すること。

7. 時間的・空間的な制約

観測記録は、特定の時間と場所における状態を記録したものである。

したがって、以下を遵守すること。

- 観測記録が存在しない期間は、状態が継続していた証拠ではない。
- 記録が存在しないことは、物理的な状態が存在しなかった証拠ではない。
- ある地点の記録は、別の地点の状態を証明するものではない。
- 後日の観測記録だけでは、変化が発生した時期を確定できない。
- 最新の記録が存在しても、その後の物理的状態が同じであるとは限らない。

観測された日付・場所と、推定された期間・範囲を明確に区別すること。

8. 出典の明示

リポジトリの記録を利用する場合、各主張を出典まで追跡できる情報を保持すること。

利用可能な場合は、以下を明示すること。

- 観測日（"date"）
- 観測ID（"id"）
- 場所（"location"）
- 原本のファイルパスまたは正規URL

出典情報は、それが根拠となる主張の近くに記載すること。

複数の観測記録を組み合わせる場合は、分析の各部分がどの記録に基づくものかを明確にすること。

公式情報を併用した場合は、公式情報についても別途その出典を示すこと。

9. 基本原則

このリポジトリを、相互に関連する物理的観測記録のアーカイブとして利用すること。

調査目的に最も適した経路から探索を開始する。

利用可能な関連性を辿る。

新たな関連性が発見された場合は、必要に応じて探索を広げる。

証拠が必要な場合は、元の観測記録に立ち戻る。

調査目的に応じて、自ら探索経路を選択すること。

このプロトコルの目的は、あらゆる探索方法を規定することではない。AIが何を探すべきか、どのように探すべきか、そして十分な証拠を発見したかを自ら判断できるように、リポジトリを発見可能な状態にすることである。
