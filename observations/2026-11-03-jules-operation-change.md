Jules終了に伴うAI協働運用の変更記録

- 記録日：2026-11-03
- 対象リポジトリ：hirosaki-view
- 記録区分：AI協働運用の変遷
- 変更契機：Google Julesのサービス終了告知

1. 従来の運用

これまでは、ChatGPT・Geminiなど複数のAIで作業内容を検討し、作成した指示をGoogle Julesに渡していた。

JulesがGitHubリポジトリを編集してPull Requestを作成し、人間が確認・マージするという流れだった。

2. 変更のきっかけ

Google Julesが2026年12月31日にサービス終了予定となり、11月11日以降は読み取り専用になることが告知された。

これを受け、従来の運用をそのまま別のAIエージェントに置き換えるのではなく、必要な作業を分解して再設計することにした。

3. 新しい運用の構築

今回、最初に自動化したのは、AIが作成したMarkdownをGitHubに登録する工程。

GitHub IssueとGitHub Actionsを組み合わせ、以下の流れを構築した。

1. AIが登録用Markdownを作成する。
2. 人間がGitHub Issueを作成し、本文にMarkdownを貼り付ける。
3. "register-md" ラベルを付ける。
4. GitHub ActionsがIssueを検知する。
5. Markdownファイルをリポジトリに新規登録し、コミットする。
6. 処理完了後、Issueを自動クローズする。

2026年11月3日、Issue #48でテストを実施し、ファイル登録・コミット・Issueクローズまでの動作を確認した。

4. 新しい役割分担

- AI：情報の整理、Markdown作成、処理方法の設計
- 人間：内容の判断、Issue作成、ラベル付与、結果確認
- GitHub Actions：Issue検知、ファイル登録、コミット、Issue処理

5. 今回の変更の意味

今回の変更は、Julesの代替AIを導入したものではない。

特定のAIエージェントに依存していた作業を分解し、AI・人間・外部システムそれぞれが得意な処理を担当する構成へ変更したもの。

特に、スマートフォンからの操作を前提として、人間が毎回行っていたファイル作成やコピー作業を減らし、Issueへの投稿とラベル付与で登録できるようにした。

6. 今後の拡張

現在はMarkdownの新規登録を対象としている。

今後は必要に応じて、既存情報の整理やリポジトリの点検なども、別のラベルとGitHub Actionsで処理できる構成を検討する。

RSS・Atomへの反映や既存監査処理との整合性は、今後の確認事項とする。

7. 継続観測すること

- 日常の登録操作に必要な手間
- 自動登録の成功・失敗
- AI・人間・自動処理の役割分担の変化
- AIモデルや外部サービスの変化に伴う運用の変更

この記録は、特定ツールの導入報告ではなく、人間とAIの協働方法が時間とともにどのように変化していくかを残すための履歴である。
