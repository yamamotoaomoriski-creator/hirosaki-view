Hirosaki View FORMAT_MASTER

- Version: 1.0.0
- Status: Active
- Purpose: Raw Observationを、再生成可能なStructured Dataへ変換するための共通仕様

1. 基本方針

Hirosaki Viewは、現地で記録された物理的な観測事実と、その時点での人間の認識を保存し、時間経過に伴う状態・変化・現象を追跡するアーカイブである。

本マスターは、Raw ObservationをAIが参照・比較・分析しやすいStructured Dataへ変換するための基準を定める。

1-1. RawとStructuredの関係

- Raw：観測時点の原記録。原則として変更しない。
- Structured：Rawを本マスターに従って再構成した派生データ。
- FORMAT_MASTER：Structuredを生成する際の変換基準。

Rawを正本とし、StructuredはいつでもRawとマスターから再生成できる状態を保つ。

Structuredの生成・修正を理由にRawを書き換えてはならない。

1-2. 変換の原則

1. Rawに存在しない事実を追加しない。
2. 観測事実と推測・解釈を混同しない。
3. Rawに含まれる意味やニュアンスを、読みやすさのために消さない。
4. 曖昧な情報をAIの判断で確定させない。
5. 情報の分類・整理と、原文の改変を区別する。
6. 判断できない情報は、無理に補完せず未確定として残す。
7. 元の記録に存在する表現は、意味を変えず可能な限り保持する。

2. Structuredの基本構成

Structuredは以下の6領域で構成する。

2-1. Observation Facts（観測事実）

Rawに記録された物理的・客観的な観測内容。

- Rawの観測事実を原文に忠実に保持する。
- 情報を省略する要約は行わない。
- 原文の複数項目を統合する場合、意味や対象を失わない。
- AIが補足した情報を観測事実として追加しない。

2-2. Contemporary Context（同時代の認識）

観測時点における人間の認識・解釈・違和感・仮説・疑問。

- RawのHuman observation等を基本的に原文のまま保持する。
- 観測事実と人間の認識を分離する。
- 当時の認識を、後から得られた知識で書き換えない。
- 「違和感」「不明」「気になる点」も情報として扱う。

2-3. Structure（構造化情報）

観測対象の状態・変化・イベント・関係性を整理する領域。

State

観測時点で確認された対象の状態。

Change

過去の観測との比較によって確認できる変化。

- 比較対象が存在する場合は、その観測記録を明示する。
- 変化を確認できない場合、無理に記述しない。

Event

観測された状態が、どのようなイベントや活動の局面に該当するかを整理する。

- イベントの存在や名称はRawに根拠がある場合に記載する。
- phase（通常・準備・開催・撤収など）は、根拠がある場合に分類する。
- AIによる分類は、観測事実そのものと区別する。

Relationships

他の観測記録・場所・イベント・状態との関係性。

- prev / next / related等の関係を整理する。
- 関係性の根拠を明示する。
- 根拠のない関連付けを行わない。

2-4. AI Interpretation（AIによる解釈）

RawとStructureをもとにAIが導いた分類・分析・推論。

- Observation Factsとは明確に分離する。
- 解釈ごとに根拠となるRawの記述やStructured項目を示す。
- 推論を事実として扱わない。
- 解釈の確度と観測事実の確度を混同しない。
- 根拠が不足する場合は、その旨を明示する。

2-5. Residual（未構造化情報）

既存の項目に適切に分類できない情報を保持する領域。

Residualは不要情報の廃棄場所ではなく、現在のマスターでは十分に表現できない情報を保護する領域である。

statusは以下のいずれかとする。

- "empty"：確認した範囲に未分類情報がない。
- "unreviewed"：未確認の情報が残っている。
- "unresolved"：意味や分類を確定できない情報がある。
- "out_of_schema"：現在のマスターに適切な格納先がない情報がある。

entriesには該当する原文を保持し、AIによる言い換えで意味を変えない。

2-6. Provenance（出典・生成履歴）

Structuredの生成元と生成条件を記録する。

最低限、以下を保持する。

- source_raw：元となったRawファイル
- raw_metadata：RawのFront Matter一式
- evidence：Rawに記載された画像・資料等のファイル名
- observation_confidence：Rawに記載された観測確度
- navigation：Rawに記載された前後・関連リンク
- master_version：使用したFORMAT_MASTERのバージョン
- generator：生成に使用したAIまたはツール
- generated_at：生成日時
- master_commit：使用したマスターのGitコミットID（取得できる場合）

RawのFront Matterに存在するid、date、location、title、series、type、observer、direct_observation、prev_observation、next_observation等の情報を欠落させない。

元のRawに含まれるナビゲーション情報は、Structured側のファイル配置に合わせてリンクを書き換える場合でも、元の参照先を追跡できるように保持する。

3. 確度の扱い

観測事実の確度とAI解釈の確度は別々に扱う。

- observation_confidence：Rawに記録された観測確度を保持する。
- interpretation_confidence：AIによる解釈の確度を必要に応じて記録する。

Rawに確度が記録されていない場合、AIが独自に補完しない。

4. 情報が存在しない場合の扱い

情報の欠落を、すべて同じ意味として扱わない。

- 未記載：Rawに情報が記載されていない。
- 未観測：観測していないことが明示されている。
- 非該当：対象に該当しないことが確認されている。
- 未確定：情報はあるが判断できない。

これらを区別できる場合は区別する。根拠がない場合は状態を推定しない。

5. バージョン管理

本マスターはSemantic Versioningに準じて管理する。

- PATCH：意味や構造を変えない説明・表現の修正。
- MINOR：既存データとの互換性を維持した項目追加。
- MAJOR：既存項目の意味・構造・変換規則を変更する改訂。

改訂時は変更内容と理由をChangelogに記録する。

Changelog

- 1.0.0：初版。RawとStructuredの分離、6領域の基本構成、情報保全・出典管理の原則を定義。

6. 変換ワークフロー

1. 対象Rawを読み込む。
2. 適用するFORMAT_MASTERのバージョンを確認する。
3. Rawの記載内容を6領域に対応付ける。
4. 情報の欠落・重複・意味の変化がないか確認する。
5. 未分類情報をResidualに保持する。
6. Provenanceを記録する。
7. Structuredを生成する。
8. Rawとの照合を行い、差分を確認する。

変換は1ファイル単位から開始できるものとする。

7. 品質確認基準

Structuredの完成時には、以下を確認する。

- Rawにある観測事実が欠落していない。
- Rawにない事実が追加されていない。
- 同時代の人間の認識が保持されている。
- 観測事実とAI解釈が分離されている。
- 状態・変化・イベント・関係性が区別されている。
- 未分類情報がResidualに保持されている。
- Rawのメタデータと出典を追跡できる。
- Rawそのものが変更されていない。

本マスターの目的は、記録を均質な文章に整えることではない。

観測された事実、その時点での人間の認識、後から加わるAIの解釈を、それぞれ失わずに蓄積し、時間を越えて比較・再分析できるデータにすることである。
